# ai-building-blocks — Claude instructions

This repo is a knowledge store about the 17 building blocks of software built around LLMs. It is storage, not a document. Tools render it on demand: `/talk`, annotate, a terminal answer, a diagram.

- Start from `README.md`. It holds the id scheme, the block table, the dependency order, the request path across blocks, the glossary and the Lomem coverage.
- Each `NN-<id>.md` file holds one block as items with stable ids (C concept, F flow step, L lifecycle, E example, N number, X verbatim Lomem code, M pitfall, Q misconception, S source). Cite and request items as `<block>.<item>`, for example `gateway.F1.3`.
- When explaining or drawing, read only the items asked for. Never invent values: use the item's own facts, and say when an item is marked unverified or made up.
- When editing, keep the format: add items with new ids, never renumber existing ones, keep provenance on every fact, and add no teaching prose or rendered diagrams to the item sections.
- Code items (X) quote `~/projects/lomem` as read on 2026-10-15. Lomem moves on; when an excerpt no longer matches, update the item and its line numbers.
- `sources/` is the raw research of 14-15.10.2026. The block files win where they disagree.
- Each block's story page shows two diagrams, drawn by the shared library in claude-annotate (`docs/vz.md` there is the guide): `diagrams/<id>.map.json`, the block's architecture map, with a build order (`b`) and the walkthrough as a route (`r`, route arrows) and their captions; and `diagrams/<id>.seq.json`, the walkthrough as a lane sequence. The block file's `### Overview` holds `- Title:` (equal to the map's title, which check.py enforces), `- Caption:` and `- Refs:`. Every word on a diagram is a fact from the block's items; made-up values say "example". Edit the specs, never drawn SVG. Check with `cd ~/projects/claude-annotate && python3 tools/vz.py svg SPEC -o X.svg && uv run tools/vz_check.py check X.svg` until 0 faults, then look at its PNGs. `tools/vzlib.py` is how the site reads the library (`VZ_HOME` moves it). `/slides/` presents every map and walkthrough, and `make publish` exports each diagram as light and dark PNGs plus one PNG per build and route step.
- The reference pages (`/<block>/reference/`) draw every flow (Fn) as a lane sequence at build time: `tools/flowseq.py` converts the flow's steps and the Components table into a sequence spec, with no spec file and no hand edits. Lanes are the parts the steps name (a `K` id, "Name (K1)" or a component's own name all become that component), badge n is step F#.n, a lettered branch is an amber chip with its id, a condition other than "always" is a ✓ badge, a short ref is the chip's mono line, and the route captions are the step texts. To change a drawing, change the flow's steps or the converter. A flow whose steps name fewer than two parts gets no diagram (context.F7, context.F13, rag.F11, agents.F3, agents.F4, agents.F14, evals.F2). Check all of them with `python3 tools/flowseq.py DIR` and then `vz_check.py check DIR/*.svg`. Lifecycles (Ln) stay Mermaid state diagrams; a page loads Mermaid only when it has one.
- The home page's request path is `diagrams/home.map.json`, written by hand from README section 4: rows R0-R13 are the boxes and the route (badge n is Rn, route step n+1), and R14-R20 sit in two zones below. When a README row changes, change the spec to match.
